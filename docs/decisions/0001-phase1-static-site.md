# 0001: 第1段階は静的サイトで段階公開する

- 日付: 2026-11-26
- 状態: **決定**（運営者が推奨案を承認）
- 関連: [SONARIA_SITE_ARCHITECTURE_DRAFT_v0.2.md](../SONARIA_SITE_ARCHITECTURE_DRAFT_v0.2.md) §8・§11

## 決定

| 項目 | 決定 |
|---|---|
| 公開の進め方 | **段階公開**。講師の自己登録・本人編集（サーバ処理と DB が必要）は第2段階に回す |
| 第1段階の範囲 | ホーム、楽譜検索、作品詳細、講師検索・簡易プロフィール、About、法定表示 |
| 技術構成 | Next.js 15（App Router）＋ TypeScript ＋ Tailwind CSS v3、**静的書き出し**（`output: "export"`） |
| ホスティング | さくらのレンタルサーバ（契約済み）。静的ファイルを配信する |
| 言語別 URL | 最初から `/ja/...` と `/en/...` に分ける |
| `/` の言語振り分け | さくらの `.htaccess` で行う。①Cookie `sonaria_lang`（本人が選んだ言語）②ブラウザの `Accept-Language`（日本語なら `/ja/`、それ以外は `/en/`）の順 |

## 理由

- 第1段階の機能は、サーバ処理がなくても成立する
- 講師ディレクトリは承認済み B案（簡易プロフィール → 本人のサイト・SNS）なので、登録を外部フォームで受け、管理人が審査してデータに追加する運用で静的に掲載できる
- 後から言語別 URL に変えると SEO に影響するため、最初から分ける

## 制約と次に決めること

- **講師登録**: 第1段階は外部フォーム＋管理人による手動データ化。[要決定] 使う外部フォームサービス、本人確認資料の受け取り方法（公開ストレージに置かない）
- **楽譜検索**: 検索はブラウザ内で行う。試験移行の 20〜30 件では問題ない。[要決定] 何件を超えたら検索方式（索引ファイルの分割・外部検索など）を見直すか
- **静的書き出しで使えないもの**: `next/image` の最適化、Server Actions、API Routes、ミドルウェア
- **第2段階**: 講師の自己登録・本人編集・管理画面。さくらの契約プランでサーバ処理・DB が使えるかを調べてから構成を決める（[要検証] プラン名の確認）
- **ドメイン**: [要決定] 本番ドメインが決まったら `NEXT_PUBLIC_SITE_URL` に設定し、canonical・hreflang を有効にする
