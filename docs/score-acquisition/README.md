# SONARIA: GPT ⇄ Claude 楽譜収集・版選定連携 v1

## 目的
GPTが約1時間ごとにIMSLP等の公開情報を調査し、未収録の作品と有望な版を **候補リスト** としてGitHubに記録する。Claudeは候補を受け取り、合法的に取得できるPDFの回収、ファイル検査、ページ化を担当する。**候補の記録はダウンロード・権利承認・公開を意味しない。**

## 読み込み順序
1. リポジトリの `CLAUDE.md` と `docs/workflow.md`、`docs/SONARIA_FREE_SCORE_LIBRARY_AND_CATALOG_v1.0.md`
2. この文書
3. `docs/score-acquisition/queue.json`
4. 既存の作品・版・ファイル台帳（実際のパスを探索し、未確認ならその旨を記録）

## 対象の巡回順序
**ハイドン → モーツァルト → ベートーヴェン → ブラームス**。各作曲家で **弦楽四重奏 → ヴァイオリン・ソナタ → チェロ・ソナタ** の順。作品が存在しないジャンルは理由を記録してスキップ。ジャンル内で作品番号・目録番号順を基本とし、未掲載を優先。既存収録は「同一作品」だけでなく「同一版／同一PDF」の重複も照合。全件を網羅できたと確認できるまで完了扱いにしない。

## 担当
**GPT（企画・候補調査）**
- 各回、未処理の候補を可能な範囲で複数件調査。実物URLと作品／版の出典を明示する
- 候補は `candidate`、情報不足は `research_needed`。作品の実在・内容・再配布権・版の良否を推測で「確認済み」にしない
- 既存キューを読んで重複登録を避け、作曲家・ジャンルの順番を保つ
- 権利・版・ファイルを別々に評価し、Claudeに確認すべき事項を残す
- 原則 GitHub の作業ブランチ＋PRを使い、mainへ直接pushしない。保存成功時はSHAとPRを記録

**Claude（実装・PDF取得）**
- `candidate` のみを候補として確認し、IMSLPの利用条件・ダウンロード方法・公開権利を個別検証
- 原曲とPDFの題名、作曲者、作品番号、楽章、編成、パート譜、ページ順序、画質、スキャン欠損、出版社・校訂者・版情報を調べる
- 既存の `Work / Edition / ScoreAsset` 設計を維持。重複とPDFハッシュをチェック
- 否認／不明は `held` として理由を残す。PDFは公開しない
- 検証済みでも管理人が権利ステータスを承認するまでは `rights_status=approved` とせず公開しない
- PDFの公開、既存ファイルの削除、権利承認、本番移行は管理人承認後だけ
- 作業結果と検証証拠を同じレコードに追記し、検査結果・PR URLを残す

## 共有ステータス
`candidate` → `research_needed` / `claude_review` → `downloaded` → `quality_passed` → `awaiting_rights_approval` → `approved_for_publish` → `published`。
問題があればどの時点からでも `held`。`published` は実際の公開URLと検証記録がある場合のみ。

## 品質チェック表（チェックごとに根拠／日時を記録）
- [ ] 作品名、作曲家、作品番号、曲種が一致
- [ ] IMSLPの作品ページURLと版・ファイルの識別子を記録
- [ ] 出版社／出版年／校訂者／編曲者を確認（不明は不明と記す）
- [ ] 原典・信頼できる校訂・良好な出版譜を優先する合理的な版比較
- [ ] 必要な楽章、スコア、各パート譜の収録範囲が揃う（意図した抜粋は明示）
- [ ] PDFが開き、全ページを確認し、音符・臨時記号・スラーの可読性が十分
- [ ] 題名とPDFの中身が一致し、誤リンクでない
- [ ] 重複（Work/Edition/PDF SHA-256）確認
- [ ] 出典・再利用条件・日本国内の権利／校訂／版面／画像等を確認
- [ ] 管理人が `rights_status=approved` を明示的に承認
- [ ] ダウンロード／プレビュー／モバイル／ページ生成／リンク検査
- [ ] 公開URLを実際に開き、正しいファイルであると確認

## 項目の記録
`queue.json` の1候補に `id, composer, category, work_title, opus_catalog, work_url, edition, edition_url, source_file_url, score_parts, status, research_evidence, checklist, rights_status, notes, updated_at, owner, publication_url` を持たせる。未知の値は空欄または `unknown` を使い、架空データで埋めない。IDは一意で固定。検証後に版ごとにレコードを分けてよい。

## 運用上の禁止
- クローラー制限、CAPTCHA、課金、レート制限等を回避しない。IMSLPの規約・robots・技術的制約に従う
- 取得可＝再配布可とみなさない
- 不明な作品や版情報を捏造しない
- 公開サイトから個人情報・未承認PDFを露出させない
- 一時間ごとのGPT調査は候補調査のみ。実PDFの回収や本番公開を自動承認しない

## 進捗報告
各回：新規候補件数／重複スキップ件数／保留件数／確認した根拠URL／保存コミットSHA／PR URL／次の対象。未保存なら未保存と報告。
