# 楽譜 PDF の受け入れ手順（管理人向け）

GPT が楽譜収集キュー（PR #10 の `docs/score-acquisition/queue.json`）に候補を記録します。IMSLP は robots.txt で自動ダウンロードを禁止しているため、Claude は PDF を自動で取りに行きません。そこで **PDF の取得だけを管理人がブラウザで行い**、検査は自動で行います。

## 手順

1. `ci/score-intake` ブランチの **`download_list.md`**（取得リスト）を開きます。候補ごとに作品ページへのリンクとファイル番号が並んでいます（作曲家の優先順）。サイトに掲載中の作品は、足りない総譜だけを載せています。
   キューの候補の IMSLP ページ（`edition_url`）を開き、記録されている番号（`imslp_file_id`、例: `#39781`）のファイルをダウンロードします。
   - **ファイル名は変えないでください。** IMSLP のファイル名（`IMSLP39781-PMLP….pdf`）に入っている番号で、どの候補のどのパートかを判定します。
2. GitHub の **Releases → 「score-intake」（Draft）→ Edit** を開き、PDF をドラッグして添付します。最後に **「Save draft」** を押します（**「Publish release」は押さない**）。
   - 下書きのリリースは管理者にしか見えません。サイトにも公開リリースにも出ません。
3. 検査を始めます。どちらかの方法で行います。
   - Claude に「受け入れ検査して」と頼む
   - Actions → **Score intake** → **Run workflow**（main にマージした後に使えます）
4. 結果は `ci/score-intake` ブランチの `report.md` に出ます。

## 自動で検査すること

| 検査 | 内容 |
|---|---|
| 対応付け | IMSLP 番号から、キューの候補とパート（またはスコア）を特定 |
| ファイル | PDF として開けるか、ページ数がキューの記録と合うか |
| 重複 | サイト掲載中の PDF・受け入れ済みの PDF と同じでないか（SHA-256） |
| パート名 | 1 ページ目の文字（OCR）からパート名を読み、想定と合うか |
| 楽章 | キューに書かれた楽章の速度標語（Allegro・Menuetto など）が本文にあるか（目安です。OCR が読み落とすことがあります） |
| 視認性 | 解像度・コントラスト・くっきり度・インク量（既存の楽譜と同じ基準） |

あわせて、キューの全候補をサイトの掲載状況と照合します（`site_duplicates.md`）。

## しないこと

- 公開、権利ステータスの変更（`rights_status=approved` は管理人の承認が必要）
- IMSLP など外部サイトへのアクセス
- 公開リポジトリへの PDF の保存（検査で使うのは下書きリリースの添付だけです）

検査を通った PDF をサイトに載せるときは、既存の移行の手順（`tools/score-migration/migrate.py`）で、統一名とメタデータを付けて登録します。
