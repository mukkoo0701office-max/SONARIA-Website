## 2. 仕組み

### 料金マスタ [確定: 実装済み]

- `public.price_items`（`supabase/migrations/20261128000005_pricing_payments.sql`）。1 行 = サービス × 項目 × 有効開始日
- 改定は**新しい行を足す**だけ。過去の行は書き換えない（過去案件の金額は案件側のスナップショットで固定）
- 有効開始日は今日（日本時間）以降のみ。今日から有効な行は上書き不可
- 管理画面「料金」で一覧・履歴・追加（`admin_add_price`）
- 誰でも読める（申込フォームが表示に使う）。書き込みは管理人の関数だけ

### 料金の計算 [確定: 実装済み]

- 計算は 1 つの純粋な関数（`supabase/functions/_shared/pricing.ts`）。画面は同じ内容のコピー（`frontend/src/lib/orders/priceEngine.ts`）を使い、**2 つが同一であることをテストで確認**する
- 金額は最小単位の整数（JPY は円、USD はセント）。端数は最後に 1 回だけ四捨五入
- 受付時に Edge Function（`submit`）が**データベースの料金で計算し直して** `submissions.server_quote` に保存する。画面から送られた金額（`estimateTotal` など）は参考値で、計算には使わない

### 通貨の決め方 [確定: 実装済み・2026-11-29 改定]

| 段階 | 何で決めるか | 信頼度 |
|---|---|---|
| 画面の表示 | 端末のタイムゾーン（`Asia/Tokyo` なら日本）。判定できなければ円で仮表示し「仮」と明記 | 仮。言語とは無関係 |
| 受付（サーバー） | アクセス元の国（前段が国のヘッダーを付ける場合）を優先し、無ければ画面の推定 | 参考。`region` に保存 |
| 確認 | アクセス元の国と端末の推定が食い違えば、管理画面に警告 | — |
| 確定 | 管理人が確定金額を入れた通貨で料金区分を確定（円＝日本、ドル＝日本以外。ドルなら銀行振込はカードに戻す） | 確定 |
| 決済（Phase 3） | 確定金額の通貨で Checkout を作る。カード発行国が区分と違えば「要確認」 | — |

- 利用者が通貨・地域を選ぶ欄は置かない（指示書 §2-1、2026-11-29 運営者決定）。銀行振込の選択肢は、日本と判定できたときだけ出す
- [要検証] Supabase Edge Functions にアクセス元の国のヘッダーが付くかは公式に保証されていない。付かない場合は端末の推定だけで動く（どちらも改ざんできるが、金額は管理人が確定するまで請求されない）

### 案件と金額 [確定: 実装済み]

- `submissions` に追加した列: `region`、`region_detected`、`currency`、`payment_method`、`server_quote`、`confirmed_amount`・`confirmed_currency`・`confirmed_at`・`confirmed_snapshot`
- 金額の確定は `admin_confirm_price`
  - 決済済みなら拒否する。追加料金は `payments.purpose = additional` の別の決済にする
  - 金額を変えると、未払いの古い請求（`pending`・`link_sent`）を取り消す
- 状態に「入金待ち（`awaiting_payment`）」「入金済み（`paid`）」を追加した
- **確定金額のある案件は、入金の合計が確定金額に届くまで「入金済み」「対応中」にできない**（`admin_update_submission` で拒否）

### 決済の記録 [確定: 表のみ実装]

- `public.payments`。1 件 = 1 回の請求（カードの 1 セッション、または振込の 1 回の案内）
- 状態: 作成済み → 案内済み → 入金済み／不足／超過、失敗・期限切れ・取り消し、一部返金・返金済み、チャージバック
- 決済の記録がある案件は削除できない（会計の記録を残す）
- 管理人だけが読める。書き込みは Phase 3・4 の関数（Webhook・振込の手動記録）

## 6. 銀行振込の手動管理 [確定: 実装済み]

| 操作 | 関数 | 規則 |
|---|---|---|
| 振込案内を送った | `admin_record_bank_notice` | 確定金額（円）が必要。メールを送ってからチェックを入れて記録（コピー・メールアプリを開くだけでは記録しない）。案件は「入金待ち」へ |
| 着金 | `admin_record_bank_receipt` | 金額・着金日（未来は不可）・メモ。合計で 入金済み／不足／超過。全額で案件は「入金済み」へ（制作開始は管理人） |
| 返金 | `admin_record_bank_refund` | 振り込み返した後に記録。着金の合計まで。超過分だけ返せば「入金済み」に戻る |
| 取り消し | `admin_cancel_payment` | 未払い（作成済み・案内済み）だけ |

- 同じ操作の再送（二重クリック・再試行）は `request_id` で 1 回にまとめる
- 振込先の口座情報はリポジトリに置かない。返信テンプレートの入力欄に管理人が入れる（下書きと一緒に管理画面の DB に保存）
- 返信テンプレートに「カード決済の案内」「銀行振込の案内」「作業開始のお知らせ」と、キャンセル規定・全額返金の文を追加

## 7. 楽譜 PDF のアップロード [確定: 実装済み]

| 項目 | 内容 |
|---|---|
| 保存先 | 非公開バケット `submission-files`（PDF のみ・1 ファイル 20 MB。バケットの設定でサーバーが拒否） |
| 件数 | 1 件の申込に 3 ファイルまで（任意） |
| アップロード | Edge Function `upload-url` が 1 回限りの署名付き URL を発行。Origin を確認し、送信元ごとに 1 時間 20 回まで（`UPLOAD_LIMIT_PER_HOUR`） |
| パス | `pending/日付/ランダムID.pdf`。利用者のファイル名はパスに使わない |
| 申込 | 受付関数がパスの形と**実在**を確かめてから保存（アップロードしていないパスは拒否） |
| 閲覧 | 管理人だけ（storage のポリシー）。管理画面で「開く」を押すと 5 分だけ有効な URL を発行 |
| 利用者 | 自分のファイルも含めて読めない・一覧できない |
