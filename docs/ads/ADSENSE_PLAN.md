## 1. 配置

| ページ | 枠 | 位置 |
|---|---|---|
| 楽譜の詳細 | AdSense 1 枠（通常のディスプレイ広告） | 出典・更新日の後（「この楽譜について」を廃止した 2026-11-28 以降）。ダウンロードボタンとの間に概要・動画・出典を挟む |
| 楽譜の詳細 | Amazon 1 枠 | ページ最下部（関連作品の後）。AdSense とは本文・動画・出典・報告・関連作品を挟んで分ける |
| 作曲家 | AdSense 1 枠 | 作品一覧の後（運営者の決定 2026-11-28）。下部の広告・アフィリエイト枠とは関連作曲家・出典を挟む |
| カテゴリ | AdSense 1 枠 | 作品一覧の前（下部の広告・アフィリエイト枠と並ばないようにするため） |
| 作曲家・カテゴリ | Amazon 1 枠（設定があるとき） | ページ下部 |
| 申し込み・お問い合わせ・講師登録・演奏依頼・法務・管理画面 | なし | 広告を置かない（CLAUDE.md） |

理由: AdSense のポリシーは、ダウンロードボタンの近くに広告を置くと誤クリックを招くとして、広告をダウンロードリンクから離すよう求めている。

## 2. 表示のルール（実装済み）

- 広告の上の表記は「広告」（英語ページは「Advertisement」）だけ。Google が認める表記は「スポンサーリンク」／「広告」
- ダウンロードを広告の閲覧条件にしない。広告を一定時間強制表示しない。独自のポップアップ広告を作らない
- 自動クリック・表示回数の水増し・広告の自動更新をしない。広告を新しいウィンドウで開くよう変更しない
- 広告はダウンロードボタンと見た目を変える（ボタンの形・色を使わない。上下の細い区切り線と「広告」の表記だけ）
- 広告が表示されなくても（未接続・広告ブロッカー）、PDF のダウンロードは通常どおり使える。枠の高さ（250px）を先に確保し、レイアウトのずれを抑える
- 広告スクリプトは広告枠のあるページだけで、ページの読み込みが終わってから読み込む（`strategy="lazyOnload"`）

| 広告形式 | 初期設定 | 管理する場所 |
|---|---|---|
| 通常のディスプレイ広告 | 1 枠 | SONARIA（`data/ads.ts`） |
| 全画面（ビネット）広告 | OFF | Google（AdSense の管理画面「自動広告」） |
| アンカー広告 | OFF | Google（同上） |
| 自動広告 | OFF | Google（同上）。使う場合は `autoAdsExcludedPaths` と同じページを AdSense の「ページの除外」に登録する |
| 独自ポップアップ広告 | 使用禁止 | — |
| ダウンロード前の強制広告 | 使用禁止 | — |

## 3. 未接続の間の動作

| ビルド | 動作 |
|---|---|
| 本番（さくら） | 広告コードを読み込まない。何も表示しない（ダミー広告を出さない）。CI の「No AdSense code or preview slot in production build」で検査 |
| GitHub Pages のプレビュー・`next dev` | 広告枠の位置だけ、点線の枠と「未接続」の説明で表示する |

接続の条件（`adsenseUnitReady`）: `enabled: true`、`client` が `ca-pub-` ＋ 16 桁、広告ユニットの `slot` が数字。どれかが欠けていれば読み込まない。

## 4. 接続の手順（運営者の承認が必要）

1. 本番ドメインでサイトを公開し、AdSense に申し込む（サイトの所有権の確認・審査）
2. 審査に通ったら、ルートに `ads.txt`（`google.com, pub-XXXXXXXXXXXXXXXX, DIRECT, f08c47fec0942fa0`）を置く → `frontend/public/ads.txt`
3. 広告ユニット（ディスプレイ広告・レスポンシブ）を 1 つ作り、`data/ads.ts` の `client` と `units["work-after-downloads"].slot` を設定、`enabled: true` にする（PR で）
4. AdSense の管理画面で、自動広告・ビネット・アンカーを OFF のまま確認する
5. 「プライバシーとメッセージ」で欧州（EEA）・英国・スイス向けの同意メッセージを設定する（§5）
6. 管理画面の広告分析を AdSense Management API（OAuth、読み取りのみ）に接続する。認証情報はサーバー側の環境変数だけに置く

## 5. Cookie・同意管理

| 地域 | 対応 |
|---|---|
| EEA・英国・スイス | パーソナライズド広告を出すには、Google 認定の CMP（IAB TCF に対応）が必要。AdSense の「プライバシーとメッセージ」（Google の CMP）を使うのが最も簡単。設定しない場合は「パーソナライズされていない広告」に限定する |
| 米国の一部の州 | Google の CMP が米国州法向けのメッセージにも対応。必要に応じて有効にする |
| 日本 | 個人情報保護法（Cookie 単体は原則として個人情報ではないが、他の情報と結び付ける場合は注意）。電気通信事業法の外部送信規律（2023 年 6 月施行）が SONARIA に適用されるかは **[要検証・法務]**。適用される場合は、外部送信先（Google・Amazon など）・送信される情報・目的の公表が必要 |

方針: 訪問者の大半は日本からのため、まず Google の CMP を EEA・英国・スイス向けに有効にし、日本向けにはプライバシーポリシーで広告 Cookie と外部送信を説明する。

## 6. プライバシーポリシーに追加する事項（現在は準備中のページ）

1. Google AdSense を利用していること。Google を含む第三者配信事業者が Cookie を使い、過去のアクセス情報に基づいて広告を配信すること
2. 利用者が Google の「広告設定」でパーソナライズド広告を無効にできること（オプトアウトの方法）。Google のポリシーと規約のページへのリンク
3. Amazon アソシエイト・プログラムに参加していること（「Amazon のアソシエイトとして、SONARIA は適格販売により収入を得ています」）
4. アクセス解析（導入する場合）の名称・取得する情報・目的・オプトアウト
5. 外部送信の一覧（送信先・送信される情報・利用目的）。§5 の要検証の結果に応じて
6. 欧州などからのアクセスに対する同意管理（CMP）を使っていること
7. お問い合わせ窓口

## 7. 管理画面（`/admin/ads/`。プレビュー用ビルドのみ）

- **広告分析**: AdSense 推定収益・ページ RPM・広告表示回数・広告枠別・ページ別（以上 **AdSense API**）、PDF ダウンロード数・ダウンロード率・導入前後の比較（以上 **サイト内の計測**）。出どころをバッジで区別する。PV と広告収益、ダウンロード数と広告収益は、2 軸を重ねず上下に並べて比べる
- **広告管理**: SONARIA 側で管理する設定（AdSense の有効／無効・サイト運営者 ID・対象ページ・ページ別の広告枠・Amazon の有効／無効）と、Google 側で管理する設定（自動広告・ビネット・アンカー・CMP・ads.txt）を分けて表示する
- 未接続のため、表示しているのはデモデータ。取得できない指標を実績として表示しない

## 8. 将来必要な AdSense の設定（まとめ）

- AdSense アカウント（サイト運営者 ID）・サイトの審査
- `ads.txt`
- 広告ユニット 1 つ（楽譜詳細・FAQ の後）
- 自動広告・ビネット・アンカーは OFF
- プライバシーとメッセージ（EEA・英国・スイスの同意）
- 必要に応じて広告の審査センターでのカテゴリのブロック（楽譜・音楽教育の利用者に合わない広告）
- AdSense Management API（管理画面の分析用。サーバー側で OAuth）
