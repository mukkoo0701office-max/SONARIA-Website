## 1. 演奏依頼の見積もりフォーム（`/ja/performance/`）

| 項目 | 実装 |
|---|---|
| 見出し画像 | 下層ページ共通の高さ（PC 6:1・スマホ 3:1）。最初の画面にフォームが見える |
| 日程 | 「決まっている／候補が複数ある／未定」。日付＋時間帯（午前・午後・夜）＋時刻（任意）。候補は 3 件まで。未定なら「時期の目安」 |
| 予算範囲 | 単一選択（「未定・相談したい」を含む） |
| 編成 | ソロ・デュオ・トリオ・弦楽四重奏・その他／未定＋楽器の希望（任意） |
| 備考 | 会場・演奏時間・イベントの種類・曲目など |
| 連絡先 | お名前・メールアドレス・プライバシーポリシーへの同意 |
| 流れ | 入力 → 確認 → 送信 → 結果。価格の自動確定・自動請求はしない |
| スパム対策 | 見えない入力欄（ハニーポット）。入力があれば送らない |

### [要決定]

1. **予算範囲の区切り**（仮: 5 万円未満／5〜10 万／10〜20 万／20〜30 万／30 万円以上／未定）。値は `frontend/src/data/orders/performance.ts`、表示名は辞書の `performanceQuote.budget.options`。正式な料金表ではなく目安として伺う旨を画面に書いている
2. **送信先**。環境変数 `NEXT_PUBLIC_PERFORMANCE_ENDPOINT`（未設定なら `NEXT_PUBLIC_ORDER_ENDPOINT`）に JSON を POST する。どちらも未設定の間は「オンライン送信は準備中です。この内容はまだ運営者に届いていません」と表示し、受付完了には見せない
3. 送信先が決まるまでページは `noindex`（申込ページと同じ扱い）。sitemap にも入れていない

## 2. 講師登録（`/ja/teachers/register/`）

- 導線: 講師検索ページの見出しのすぐ下と、トップページの「講師を探す」の下に「講師として無料登録する」
- フォームは「公開されるプロフィール」と「審査用の情報（本名・メール。公開しない）」に分けている
- レッスン料金の項目は作らない。確認書類・写真はフォームで受け付けない（審査時にメールで案内）
- 年代は任意（「公開しない」が初期値）。生年月日は聞かない

### 掲載までの流れ（第 1 段階・静的サイト）

```
申請（フォーム） → submitted → under_review（管理人が確認・必要なら書類をメールで依頼）
  → approved → 管理人が frontend/src/data/teachers.ts の publishedTeachers に追加 → published（PR をマージして公開）
却下・修正依頼・掲載停止・取り下げも、管理人が publishedTeachers を編集して反映する
```

- **自動では一切公開しない。** 公開されるのは `publishedTeachers` に入っている講師だけ（既存の仕組みのまま）
- 申請データ（本名・メールなどの審査用情報）はリポジトリに保存しない

### [要決定]

1. **申請の送信先**。環境変数 `NEXT_PUBLIC_TEACHER_APPLICATION_ENDPOINT`。本人確認用の情報を含むため、統合申込とは別の送信先にしている。未設定の間は「まだ届いていません」と表示する
2. 第 2 段階（講師の自己登録・本人編集・管理画面・DB）は CLAUDE.md のとおり未決定。さくらの契約プランで動くものを調べてから決める
3. 審査の基準（学歴の確認方法、書類の保管と削除の期限）

## 3. ホームの楽譜検索

- 上から: 曲名・作曲家（日英・別名・作品番号を横断）→ 演奏人数（すべて／1〜4 人／5 人以上）→ 譜面の種類 → 楽器・編成・種類（1 行のセレクト）
- 条件を変えるたびに「203 作品中 N 作品が該当」を表示。「この条件で探す（N 件）」と「すべての楽譜を見る」の 2 つの導線
- 判定は `frontend/src/lib/scores/filters.ts` を楽譜検索ページと共有する（トップの件数と検索ページの件数が一致する）
- 楽譜検索ページにも「演奏人数」「譜面の種類」の絞り込みを追加（URL のクエリ `players` / `sheet`）

### 譜面の種類の判定

- 実在するファイルの `part` だけで判定する（`frontend/src/lib/scores/sheetType.ts`、テスト `frontend/tests/sheetType.test.mjs`）
- 「スコアあり」= part が `score` のファイルがある。「パート譜あり」= それ以外のファイルがある。「両方あり」= 両方ある
- ヴァイオリンとピアノの曲で「ピアノ（ヴァイオリン付き）」のファイルしか無い場合は、`part` が `piano` のため「パート譜」扱いになる。スコアとして扱いたい場合はカタログの `part` を見直す
- 2026-11-27 時点の内訳: パート譜のみ 169 作品、両方あり 30 作品、スコアのみ 4 作品
