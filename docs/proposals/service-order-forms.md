## 4. 送信の接続 [要決定]

- 現在は送信先が未設定のため、「この内容で申し込む」を押すと **「オンライン送信は準備中です。お申し込みはまだ運営者に届いていません」** と表示します。送信できたようには見せません。入力内容は「申込内容をコピー」で控えられます。
- 送信先は環境変数 `NEXT_PUBLIC_ORDER_ENDPOINT`（JSON を POST）。静的書き出しのため API Routes は使っていません。
- 候補: PR #7 の外部バックエンド。PR #7 には `/lessons/apply/`・`/bowing/apply/` の個別フォームがあるため、マージ時に次のどちらかを決める必要があります。
  - A（推奨）: 個別フォームを `/apply/?service=…` へ統合し、PR #7 のバックエンドを送信先にする（受信側に録音の項目を追加）
  - B: 個別フォームを残し、統合フォームは見積もり専用にする
- 保存・メール通知・添付ファイル（楽譜・音源）の扱いはバックエンド側で決める。**リポジトリに顧客情報・楽譜・音源は保存しない。**
- お問い合わせページ（`/contact/`）は準備中のため、未接続時に案内する窓口がまだありません。

## 5. その他

- 申込ページは送信が接続されるまで `noindex` にし、sitemap に入れていません。
- 楽譜ページの運弓バナー（`BowingBanner`）は統合フォームへ移動し、作曲家・曲名・パートを「対象の楽譜」の初期値に入れます。バナー内の料金表示は辞書の文言のため、料金を変えるときは `config.ts` と合わせて辞書（`library.bowing.prices`）も直す必要があります。
- 入力欄の枠は `border-muted`（#667085、白地で 4.97:1）を使っています。デザインシステムの `--color-border`（1.32:1）は入力欄の枠として WCAG 1.4.11 の 3:1 に届かないためです。専用トークンを追加するかは [要決定]。
