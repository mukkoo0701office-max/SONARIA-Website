# SONARIA 演奏依頼・講師登録・ホーム検索 改修仕様案（2026-11-27）

Status: **新規ユーザー要望に基づく実装指示案**。本番公開・mainマージは未承認。
参照: `CLAUDE.md`, `docs/workflow.md`, `docs/SONARIA_UI_DESIGN_SYSTEM_v1.0.md`, `docs/SONARIA_TEACHER_DIRECTORY_UI_SPEC_v1.0.md`, `docs/SONARIA_FREE_SCORE_LIBRARY_AND_CATALOG_v1.0.md`。

## 1. 演奏依頼・見積もり

- 演奏依頼ページのヒーロー/ヘッダー部分の**縦幅を現状の約半分**にする。共通サイトナビゲーション全体を半分にする指示ではない。画面幅別に文字が潰れないことを確認。
- ファーストビューで「演奏のご依頼・お見積もり」フォームを見せる。必須の主項目は「日程」「予算範囲」「編成」「備考」。返信に必要な氏名・メールアドレスも取得。日程未定・複数候補・予算未定にも対応。
- 日程: 日付と任意の時間帯。予算: 複数のレンジから単一選択、応相談。**具体的レンジの金額は未確定**（仮UIの例を正式価格と扱わない）。
- 編成: ソロ、デュオ、トリオ、弦楽四重奏、その他／未定。必要なら楽器・人数を備考で指定。
- 備考: 会場、演奏時間、イベント種別、曲目希望等を自由記述。
- 主要 CTA「無料で見積もりを依頼する」。入力確認 → 送信 → 受付完了。**価格の自動確定や自動請求はしない**。管理側に安全な手段で通知し、内容確認後に個別見積もり返信。
- バリデーション、スパム対策、プライバシー同意、個人情報を GitHub に保存しないこと、メール/管理者への通知失敗時の表示を要件とする。
- 静的 Next.js export の第1段階では API Routes / Server Actions を使用しない。実際の送信方法は既存インフラに適合する安全な外部フォーム/バックエンドを選定して提案する。実際の送信が動かない場合は本番で成功表示をしない。

## 2. 講師を探す → 講師登録

- 「講師を探す」の検索導線のすぐ近くに、明確な**「講師として無料登録」ボタン**と短い説明を設置。広告と誤認させない。
- ボタンは日英それぞれの**独立した講師登録ページ**へ遷移（例: `/ja/teachers/register/`, `/en/teachers/register/`）。講師ごとのブログを作るのではなく、登録フォーム専用ページでよい。
- フォーム: 表示名、かな、ローマ字、メール、音大在籍/卒業情報、指導楽器（ピアノ/木管/弦/金管）、対応地域/最寄り駅/交通時間、レッスン形態、対象レベル、短い自己紹介、外部サイト・SNS、任意の写真と公開同意。レッスン料金の項目は設けない。公開用情報と本人確認用情報を分離する。
- **管理者の明示的な承認までは一切公開しない**。submitted → under_review → approved → published。却下・修正依頼・掲載停止・取下げにも対応。検索インデックスは published のみ。
- 管理人向けに申請一覧、内容確認、承認/非承認、公開停止、更新履歴を想定する。第1段階の静的サイトでは自動承認管理システムを仮定せず、フォーム受付→管理人による確認→承認済みデータの手動追加でも可。第2段階の認証/DB/管理画面は別途設計・承認。
- 公開された講師は承認済みB案に従い検索結果→SONARIA内の簡易プロフィール→外部サイト。**講師ごとのブログ記事は作らない**。料金無料、優先掲載なし。

## 3. ホームの楽譜検索改善

- 承認済みデザインのネイビー・ゴールド・オフホワイト、チップ、検索結果の動作は維持。
- ヒーローで「無料楽譜ライブラリ」を簡潔に示し、**最も上に日本語/英語・別名横断の曲名/作曲家検索**。
- トップに**演奏人数（すべて/1/2/3/4/5人以上）**を即時選択できるチップを配置。次に楽器/編成、楽曲形式をコンパクトに置く。
- 「条件から探す」と「すべての楽譜を見る」の２導線を目立たせる。検索対象と一覧は同じデータソース。
- 詳細検索の折りたたみ内に作曲家、難易度、時代、調性、拍子、国、長さ、編曲可否、権利条件などを整理し、項目過多を避ける。詳細条件を閉じても既存の選択は維持する。
- 新規フィルターとして**譜面種類：スコア譜 / パート譜 / 両方あり**を提供。検索インデックスは Edition / ScoreAsset レベルの実在ファイル種別から判定し、スコアのみをパート譜ありと誤表示しない。作品詳細はスコアとパートを分けて表示。権利未承認はDL不可。
- 検索結果数と全公開作品数を明確に区別。キーワード＋複数絞込のAND条件、リセット、URLクエリ保持、戻る操作、0件表示を実装。モバイルでは最初の検索画面を縦長にしすぎない。
- 作品数には実データのみ使用。架空の曲数・PDF数を本番表示しない。SEO、日英対応、キーボード操作を検証。
